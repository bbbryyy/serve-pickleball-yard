# Store POS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Staff sell store items from a phone, restock, record cash-outs, and close the day against all desk money; admins manage items, stock corrections, and see store revenue, cost, profit and losses.

**Architecture:** New Postgres tables (`store_items`, `store_stock_moves` ledger, `store_sales`, `store_sale_lines`, `store_cash_outs`, `store_daily_closes`) with security-definer RPCs in the same style as the Open Play migrations. Stock = sum of moves; `store_items.avg_cost` is a moving-average cache updated under the item row lock on opening/restock. Backoffice pages under `/backoffice/store`. `report_summary` gains `store` rows for the Sales page; a separate admin-only `store_report` feeds the Store report.

**Tech Stack:** Next.js 16.4.6 App Router, React 19, Tailwind v4, Supabase Postgres + RLS, zod 4, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-18-store-pos-design.md` (approved; mockups approved 2026-11-18).

## Global Constraints

- Money in whole pesos (`int`) for prices, totals, counted amounts; costs `numeric(10,2)` (average cost per unit, unit_cost on sale lines).
- Store day = service day (4AM–1AM Manila) via `public.service_slot(now(), settings)` / `current_service_date`.
- Payment methods `cash | gcash | maya`. Restock paid_from `drawer | owner | gcash | maya` (default `owner`).
- Staff: sell, cancel same-day sale, restock (incl. paid from), cash out, close day (incl. late close of an unclosed past day). Admin: plus items, opening stock, corrections, reopen, reports, and seeing any cost figure.
- **No RPC returns cost/avg/profit to staff**: staff-facing reads go through functions or columns that omit them; `store_items.avg_cost` is not selectable by staff (column grant), admins read via RPC.
- A sale goes to the current service day; refused with `day_closed` if that day's latest close isn't reopened.
- Cancel allowed only while the sale's day is open AND (it's the current service day OR caller is admin).
- Expected per method for a day = store completed sales + walk-in court bookings (`bookings.source='walk_in'`, status confirmed, by service date of `created_at`) + open play walk-ins (`open_play_payments.source='walk_in'`, approved, by service date of `created_at`) − cash outs (cash only); online GCash/Maya approved that day (bookings by `verified_at`, open play by `verified_at`, source online) are added to the GCash/Maya expected and listed by source.
- UI copy sentence case; reuse `card`, `btn-*`, `input`, `label`; phone-first Sell screen.
- Branch `feature/store`; commit per task; PR with Vercel preview at the end; live DB migrations before merge (ask owner first).

## Review Focus

1. Two phones selling the last unit at the same moment → one succeeds, other gets "Only 0 left".
2. Sale after the day is closed → refused with a clear message; reopen lets it through.
3. Restock at a new price → average cost updates; earlier sales keep their unit_cost (past profit unchanged).
4. Staff session can't read any cost (avg_cost, unit_cost, store_report) through the API.
5. Daily close expected includes court and open play walk-ins and subtracts drawer cash-outs (incl. restock paid from drawer).

### Task 1: Store schema and RPCs

**Files:** Create `supabase/migrations/20261118000005_store.sql`, `scripts/check-store.mjs`; Modify `package.json` (`"check:store": "node --env-file=.env.local scripts/check-store.mjs"`).

**Produces (SQL, security definer, `search_path=''`):**
- `admin_save_store_item(p_id uuid, p_name text, p_kind text, p_price int, p_serving_cost numeric, p_low_stock_at int, p_active boolean, p_sort int) returns uuid`
- `store_catalog() returns table(id, name, kind, price, low_stock_at, active, sort_order, on_hand int)` — no cost columns; staff+admin.
- `admin_store_stock() returns table(id, name, kind, price, serving_cost, avg_cost, on_hand, low_stock_at, active)`.
- `store_add_stock(p_item_id uuid, p_qty int, p_total_cost int, p_paid_from text, p_opening boolean default false) returns int` (new on_hand) — opening admin-only; paid_from=drawer also inserts a `store_cash_outs` row (reason "Restock: <item>").
- `admin_correct_stock(p_item_id uuid, p_qty int, p_reason text) returns int` — reason in (`expired`,`damaged`,`given away`,`count fix`); cannot take stock below 0.
- `store_create_sale(p_lines jsonb /* [{item_id, qty}] */, p_method text) returns uuid` — locks items in id order; shelf stock check `not_enough_stock:<name>:<left>`; unit_price from item; unit_cost = avg_cost (shelf) or serving_cost; inserts sale, lines, `sale` moves.
- `store_cancel_sale(p_sale_id uuid, p_reason text) returns void` — returns stock with `cancel` moves.
- `store_cash_out(p_amount int, p_reason text) returns uuid`.
- `store_day_status(p_date date) returns jsonb` — `{closed: bool, close: {...}|null}`; and `store_unclosed_days() returns date[]` (days with any desk activity before today and no active close, last 30 days).
- `store_day_expected(p_date date) returns jsonb` — `{cash, gcash, maya, breakdown: {store:{cash,gcash,maya}, court_walk_in:{...}, open_play_walk_in:{...}, online_court:{gcash,maya}, online_open_play:{gcash,maya}, cash_outs:int}}`.
- `store_close_day(p_date date, p_cash int, p_gcash int, p_maya int, p_note text) returns uuid` — refuses future date or already-closed; stores expected snapshot.
- `admin_reopen_day(p_close_id uuid) returns void`.
- `store_report(p_from date, p_to date) returns jsonb` (admin) — `{daily:[{date, method, revenue, cost}], items:[{item_id,name,units,revenue,cost}], losses:[{date, item, qty, cost}], low_stock:[{name,on_hand,low_stock_at}]}`.
- `report_summary` replaced: adds key `store: [{date, method, revenue, cost}]` (completed sales by service_date).
- RLS on all store tables: staff read except costs (revoke select on `store_items(avg_cost, serving_cost)`, `store_sale_lines(unit_cost)`, `store_stock_moves(total_cost)` from authenticated via column-level grants); no direct writes.
